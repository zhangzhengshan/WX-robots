============================================================
  企微客服机器人 —— 快速上手
============================================================

【三步启动】

1. 安装 MuMu Player 12
   下载地址：https://mumu.163.com/
   安装时一路下一步即可，默认安装到 C 或 D 盘都可以。
   安装完成后打开一次 MuMu，确认能进入模拟器桌面，然后关闭。

2. 解压本压缩包
   建议解压到 D 盘根目录，例如：D:\Derien-Robot\
   解压后确认文件夹里有 start.vbs、bot\、watchdog\、runtime\ 等。

3. 双击 start.vbs
   - 浏览器会自动打开管理页面 http://127.0.0.1:9173/
   - 首次使用会弹出 MuMu 模拟器，请用你的企业微信扫码登录（只扫一次）
   - 之后机器人会自动在群里回复 @你的消息

启动后无需保持任何窗口打开，机器人在后台运行。


------------------------------------------------------------
【机器人能做什么】

- **AI 自动回复**：有人在启用群里 @ 机器人（@它在群里显示的名字），
  机器人会读取知识库 + 大模型生成回复，自动在群里答复。
- **定时群发**：按预设时间自动向客户群推送营销内容（含图片/视频/文件）。
- **自动自愈**：机器人进程挂了、MuMu 崩了、SSH 隧道断了，看门狗会自动
  拉起；救不回来时发邮件告警。
- **邮件告警**：机器人异常时自动发邮件通知（断路器触发、心跳丢失、
  SDK 连续拉取失败、ADB 连续失败、出站发送失败、群发失败等 6 类）。
- **管理页面**：http://127.0.0.1:9173/ 可以看实时日志、切换 dry-run、
  改告警邮箱、手动触发任务。

知识库管理：把公司的产品介绍、操作手册等放到 **bot\data\kb\** 目录下
（支持 .docx / .xlsx / .txt / .md），启动时自动同步进 AI 的检索索引。
不想让机器人知道的文档，删掉对应文件即可。


------------------------------------------------------------
【如何停止】
双击同目录下的 stop.bat 即可停止机器人与看门狗。


------------------------------------------------------------
【问题反馈】
机器人出问题时，把故障现场回传给开发者：

1. 双击包根目录下的 export-diagnostics.bat
2. 它会自动收集日志、配置、数据库、截图等并打成一个诊断包
   （敏感信息自动打码：密码/授权码/密钥一律替换，私钥绝不打包）
3. 自动发邮件给开发者；同时在桌面留一份 诊断包 zip 副本
   —— 邮件发不出去时，直接把桌面上的 zip 通过微信发给技术支持即可


------------------------------------------------------------
【常见问题】

Q1：双击 start.vbs 后没反应，浏览器也没开？
A1：右键 start.vbs → "打开方式" → 选 "基于 Windows 的脚本宿主"。
    如果还是不行，双击 stop.bat 再重新双击 start.vbs。

Q2：浏览器打开了但提示"无法访问此网站"？
A2：机器人正在启动，等 5-10 秒刷新页面即可。
    如果一直打不开，看下方"查看日志"。

Q3：管理页面提示"ADB 路径未配置"？
A3：正常情况下启动器会自动探测，不需要手动填。
    如果仍然提示，说明 MuMu 装在了非常规位置（注册表/常见目录/PATH 都没找到）：
    1. 打开 MuMu 安装文件夹，找到 shell\adb.exe（比如 D:\Program Files\Netease\MuMu Player 12\shell\adb.exe）
    2. 复制完整路径
    3. 在管理页面点"配置"，粘贴到 ADB 路径框，勾选"保存后重启"，点保存
    4. 等机器人重启后即可

Q4：群里 @ 机器人没反应？
A4：按以下顺序排查：
    - 企业微信还没登录（检查 MuMu 里的企微状态）
    - @ 的名字不对（必须 @ 机器人在群里显示的名字，默认是「德润智能机器人」）
    - 当前群不是启用群（管理页面 → 群组 → 确认该群已开启「启用」开关）
    - 机器人正在处理其他消息，稍等几秒

Q5：想临时停止定时群发？
A5：管理页面 → 配置 → 把"dry-run 模式"打开 → 保存。
    开启后定时任务只创建不发送，不占用群发配额。

Q6：双击 start.vbs 弹出"未检测到 MuMu 模拟器"？
A6：说明电脑上没装 MuMu（或装在了非常规位置）。
    1. 下载安装 MuMu Player 12：https://mumu.163.com/
    2. 安装后打开一次 MuMu，确认能进入模拟器桌面，然后关闭
    3. 重新双击 start.vbs
    如果已安装仍提示，把 MuMu 的安装路径发给技术支持。

Q7：弹出"启动环境不支持"？
A7：两种情况：
    - 提示"ARM 架构"：这台电脑不是 Intel/AMD 处理器（如骁龙芯片的
      电脑），MuMu 模拟器不支持，请换普通电脑。
    - 提示"VT 虚拟化"：重启电脑进 BIOS（开机连按 Del 或 F2），
      在 Advanced/CPU 配置里开启 Intel Virtualization Technology
      （VT-x）或 SVM Mode（AMD），保存重启后再双击 start.vbs。

Q8：弹出"MuMu 分辨率不支持"？
A8：打开 MuMu 模拟器的"设置"→"显示"，把分辨率设为手机版：
    1080x1920（DPI 280），重启模拟器后再双击 start.vbs。

Q9：定时群发失败、群发助手没动静？
A9：可能原因：
    - dry-run 模式开着（见 Q5；开着时只导航不点击发送，不占用配额）
    - 群发助手里还有未发送的草稿 → 先手动清掉草稿再观察下一次定时任务
    - MuMu 模拟器没在前台（定时任务需要模拟器窗口可见）
    - 日志里有 "60011 no privilege" → 企业微信后台权限问题，需联系管理员

Q10：机器人挂了怎么办？会自动恢复吗？
A10：会。watchdog（看门狗）每 10 秒检查一次：
    - bot 进程没了 → 自动重启（失败 5 次后熔断，发告警邮件并退出）
    - MuMu 模拟器崩了 → 每小时最多自动重启 3 次
    - SSH 隧道断了 → 静默重拉，5 次连续失败后退避 5 分钟
    如果收到告警邮件（来自本机器人的邮箱），说明需要人工介入。

Q11：start.vbs 点了好几次，会不会起好几个机器人？
A11：会。当前版本没有单实例保护。正确做法：点一次后等 1 分钟，
    没起来先看 logs\launcher.log 再决定要不要重试。
    如果已经起了多个，双击 stop.bat 清掉，再重新双击 start.vbs。

Q12：MuMu 模拟器崩溃了，机器人还在跑吗？
A12：看门狗会自动检测 MuMu 崩溃并在 1 小时内尝试重启最多 3 次。
    恢复成功 → 群聊正常，data\mumu_events.log 有记录，不发邮件。
    3 次都没救回来 → 发告警邮件并退出 watchdog。


------------------------------------------------------------
【查看日志】

启动问题（start.vbs 黑屏、没弹窗、浏览器不开）：
  看 logs\launcher.log —— 这里是启动器的完整留痕，记录了 MuMu 探测、
  分辨率检测、JRE 校验等每一步。

运行中问题（群里没回复、定时群发失败）：
  看 bot\logs\ —— 按天命名，比如 bot-2026-10-08.log，保留 14 天。

出问题时把当天的日志文件 + 诊断包一起发给技术支持。

【目录说明】

根目录：
  start.vbs                启动入口（日常双击这个，黑盒后台启动）
  stop.bat                 停止入口（同时杀掉 bot + watchdog + plink）
  export-diagnostics.bat   一键导出诊断包并发邮件（问题反馈用）
  launcher.ps1             启动器脚本（start.vbs 调它，做探测+预检+写配置+拉起 watchdog）
  pack.ps1                 打包脚本（开发者用，不碰）
  logs\launcher.log        启动日志（start.vbs 黑盒，这里是唯一留痕）
  README.txt               本文件

bot\ （机器人主程序，无需手动操作）：
  run-only.bat             直接启动 bot（watchdog 调它；不要自己跑）
  config.properties        主配置（密钥/路径/模型/告警参数；已 gitignore）
  data\
    runtime.properties    启动器探测结果（adb 路径、设备端口等；自动生成，勿手动改）
    ai_prompt.txt          AI 系统提示词（改完即生效，无需重启）
    kb\                    知识库文档（docx/xlsx/txt/md，启动自动同步进数据库）
    bot.db                 SQLite 数据库（消息去重、名册、任务运行记录）
    screenshots\           UI 自动化截图（出问题时保留现场）
    mumu_events.log        MuMu 模拟器崩溃自愈记录
    tunnel_events.log      SSH 隧道断线重拉记录
  logs\                    bot 运行日志（按天滚动，保留 14 天）
  lib\                     依赖 jar（POI、SQLite、SLF4J 等）
  src\ / out\              源码与编译输出（开发者用）

watchdog\ （看门狗，自动监控进程+SSH 隧道+MuMu 自愈）：
  watchdog.ps1             看门狗主循环（bot 挂了自动拉、MuMu 崩了自动重开）
  bin\plink.exe            SSH 隧道客户端（给存档 SDK 提供 socks5 代理）

runtime\
  jre\                     捆绑的 Java 运行环境（无需系统装 Java）
