# 项目功能范围清单（定稿）

> 依据架构设计拷问三轮确认的最终结论整理。关键决策的完整推理见 `docs/adr/0001~0003` 与 `CONTEXT.md`。
> 与最初口述清单的差异（删除/重定义/反转）见第四节「边界澄清」。

## 一、项目定位

单进程 Java 机器人：入站只读官方会话存档 SDK；@回复出站走纯 ADB UI 自动化（不装 agent、不 hook、不碰协议，见 ADR-0001，仅适用 P3）；定时宣传出站走官方企业群发 API 建任务 + ADB 进群发助手点确认（见 ADR-0008）；云端 LLM + 提示词知识库回答 @提问，按节奏向多群发送宣传资料。

**规模基线**：日发送约 100 条消息，提问密度低。一切设计以此为上限，克制优先。

## 二、必须实现（18 项）

编号保留最初口述清单的编号，便于溯源。

### 入站与身份（archive / store）

| 编号 | 功能 | 定稿实现方式 |
|---|---|---|
| 1 | 群成员身份识别 + 自动 @成员 | 存档消息只有 userid；MemberRoster 维护 userid→显示名；@回复用显示名，查不到降级为不带 @ 的纯文本 |
| 21 | accessToken 生命周期维护 | 仅服务于「成员名册自动补全」：未知 userid 调企微客户联系 API 查昵称入库；每个 Secret 独立缓存、到期前自动刷新；需单独开通客户联系 Secret |
| 19 | 多群 + 群隔离 | room_map 表维护 RoomID↔群名；消息路由按 RoomID 分发；发送状态按群记录；知识库全局共享（一份企业资料） |

### AI 问答（ai）

| 编号 | 功能 | 定稿实现方式 |
|---|---|---|
| 4 | 企业上传指定格式文档 | 支持 Markdown/纯文本 + **.docx/.xlsx**（POI 转纯文本，P3 扩展，见 ADR-0007）；素材放知识库目录同步入库，总字数上限 10 万，超限单篇拒绝；保存即热生效 |
| 9 | 知识库问答规则（原「AI 静默」） | 全部知识库内容直接拼入系统提示词（不做 RAG/向量检索）：问题命中知识库→严格按原文回答；未命中→也可回答，受诚实边界约束 |
| 13 | AI 回答切分（P3 反转） | **不切分**：一次 @ 的 LLM 回复整段单条发送（2-4 句由提示词约束），见 ADR-0006；原 ≤150 字分段方案废弃 |
| 15 | 购买意图判断 | 完全在提示词层完成：AI 判断出购买/了解饮品意图时，回复附带购买引导；不设独立业务逻辑 |
| 20 | AI 诚实边界 | 提示词约束：命中知识库严格按原文；不确定时必须诚实标注；不编造 |

### 出站发送（outbound / adb）

| 编号 | 功能 | 定稿实现方式 |
|---|---|---|
| 7 | 定时发送资料（文本/图片/文件） | **P4 起改走企业群发 API（add_msg_template）+ ADB 进群发助手点确认（见 ADR-0008）**：第一刀仅文本；图片/视频/文件第二刀走素材管理 media_id + attachments（原 ADB「+→相册/文件」方案废弃，P6 批次并入 P4 第二刀）。sender 必须为群主 userid；每群每天限 1 条（管理端表单约束）；dry-run 时只校验不点发送 |
| 8 | 消息发送失败重试 | 指数退避重试 3 次（30s/2min/10min），耗尽转失败并邮件告警 |
| 12 | 消息防重复发送 | 去重指纹 = 目标群 + 内容哈希 + 5 分钟时间窗，重复入队直接丢弃 |
| 17 | 执行过程日志 | 全链路日志（监听/回复/发送/任务/告警），管理端可查看 |

### 定时宣传任务（schedule，P4 走企业群发 API，见 ADR-0008）

| 编号 | 功能 | 定稿实现方式 |
|---|---|---|
| 14 | 任务节奏 | 一次性 / 每天 / 周一到周日指定星期；创建时勾选目标群（可多选，仅限 room_map 启用群且群主为 sender）；测试期 test.target-roomid 白名单收敛单群 |
| 16 | 任务暂停 | 暂停期间错过的触发作废（停用时写 cancelled_paused）；恢复后从下一周期开始 |
| 18 | 定时防重发 | 幂等键 unique(task_id, planned_date)：进程重启、队列重放都不会同日重发；计划时间后 4h 补发窗口内开机补发，超窗一次性任务标 failed_missed、周期任务不补 |

### 管理端（admin）

| 编号 | 功能 | 定稿实现方式 |
|---|---|---|
| 5 | 管理后台 | 机器人进程内嵌 Javalin HTTP 服务，**无登录、无权限体系，打开即用，不拆独立后端**。页面：知识库编辑 / 定时任务 / 机器人相关消息 / 出站队列状态 / 运行日志 / 群映射表编辑 / 成员名册编辑 |
| 3 | 聊天记录后台查看（重定义） | 只保留机器人相关消息（@提及 + 机器人回复）入库并在后台展示；客户闲聊不入库（见第四节澄清） |

### 运维（alert / watchdog）

| 编号 | 功能 | 定稿实现方式 |
|---|---|---|
| 6 | 异常告警 | 邮件通道。6 类触发：熔断、心跳丢失（看门狗检测进程死亡并自动重启）、SDK 连败 10 次、ADB 失联、发送重试耗尽、AI 连败 5 次。同类事件 30 分钟节流一封；SMTP 配置在 config.properties |

## 四、边界澄清（与最初口述清单的差异）

| 原条目 | 最终结论 |
|---|---|
| 必做 2「敏感词检测/违规消息审核」 | **已删除**，不做敏感词检测 |
| 必做 9「AI 静默」 | **重定义**：命中知识库严格按原文回答，未命中也可回答；无静默逻辑 |
| 必做 3「完整聊天记录」vs 不做「聊天记录长期保存」 | 冲突调和：**只存机器人相关消息**（@提及+机器人回复），闲聊不入库 |
| 必做 21「accessToken」 | 先删除后**恢复**：仅服务于成员名册自动补全（客户联系 API），禁止泛化为通用 token 管理。2026-09-12 P1 设计拷问中**有意扩展**：用途增加名册全量/5 分钟轮询同步（入群自动新增、退群硬删除，事务 diff），仍禁止泛化到其他用途（见 ADR-0005） |
| 必做 15「购买意图判断」 | 不做独立业务逻辑，**全部在提示词层**完成 |
| 必做 5「要做管理后台」vs 不做「管理后台不做后端」 | 冲突调和：不做独立后端工程与登录体系，**进程内嵌 HTTP 即是全部** |
| 不做「后台选定执行群聊」 | 与必做 19/14 的调和：定时任务创建时**简单勾选目标群**即可，不做群选择器组件 |
| 必做 1 的成员名册 | 不需要人工逐条维护：未知 userid 自动调 API 补全，查不到才在管理端标记人工补录 |

## 五、技术红线

1. **单进程、单 jar**：无微服务、无独立消息队列、无分布式
2. **SQLite 单文件（WAL）**：所有持久化一张库，备份=复制文件（ADR-0002）
3. **管理端无登录**：内网自用，Javalin 内嵌，前端原生 HTML+fetch
4. **密钥只在 config.properties**：不入源码、不入版本库
5. **日发送 ~100 条**：不为此做任何并发优化；全局单发送线程串行消费
6. **LLM 只用云端 API**：知识库全量进提示词（≤10 万字硬上限），不引入 RAG/向量库（ADR-0003）
