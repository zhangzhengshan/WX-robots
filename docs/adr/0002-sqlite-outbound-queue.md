# 出站消息统一走 SQLite 持久化队列

机器人需要同时满足：发送防重复、失败重试、定时任务防重发、发送过程可后台查看。现状是内存 ConcurrentLinkedQueue，进程一挂全部丢失。

## Decision

所有出站消息（AI 回复、定时宣传任务）统一进入 SQLite `outbound_message` 表，状态机为 `待发送 → 发送中 → 已发送 / 失败`。全局仅一个发送线程串行消费，AI 回复优先于定时任务。发送成功以 ADB 截图验证消息上屏为准；失败按 30s/2min/10min 指数退避重试 3 次，耗尽转失败并触发邮件告警。防重复用"目标群 + 内容哈希 + 5 分钟时间窗"去重；定时任务防重发用"任务ID + 计划触发日期"唯一约束。重启后从表中恢复未发消息继续发送。

## Alternatives Considered

- **内存队列 + 追加日志**：重启丢未发消息，无法满足防重发与审计。否决。
- **独立消息队列中间件（RabbitMQ/Redis）**：日发送量约 100 条，纯过度设计，且引入部署运维成本。否决。

## Consequences

- 优势：一张表支撑防重、重试、幂等、审计四个需求；备份=复制一个文件。
- 约束：全局串行发送意味着定时任务大促时延受 AI 回复排队影响（日均百条量级下可忽略）。
