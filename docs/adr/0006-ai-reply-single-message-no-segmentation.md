# AI 回复整段单条发送，取消分段

2026-09-15 P3 设计拷问锁定，取代 ADR-0003 中「回答按 ≤150 字分段输出、程序按分隔符切分、超限硬切」的决定（scope 功能 #13 同步反转）。

## Decision

一次 @ 触发的云端 LLM 回复**整段作为一条出站消息**入队发送，不再做多段切分：

- source_id 从 P2 的 `at:{seq}:{segment_idx}` 收敛为 `at:{seq}:0`，一次 @ 对应 outbound_message 一行。
- 回复长度由提示词约束（成品客服提示词规定 2-4 句），程序不再做长度切分。
- 出站链路不变：仍走出站队列（pending→sending→sent/failed、source_id 5 分钟去重、30s/2min/10min 重试、截图审计）。
- LLM 调用在独立单线程 AI worker 执行，不阻塞存档监听线程与 lastSeq 推进。
- ADB `input text` 不支持换行：入队前把回复中的所有连续空白（含换行）折叠为单个空格，不删内容。
- 空 @（剥掉 @名 后无正文）不调 LLM，直接回固定闲聊引导；LLM 调用失败回固定兜底文案，60s 超时、进程内不重试。

## Alternatives Considered

- **维持 ≤150 字多段（原 ADR-0003/scope #13）**：分段降低单条阅读压力，也与 P2 多段队列同构；但业务方实测的成品提示词以「2-4 句短回复 + 一条小程序链接」为输出形态，整段更自然，分段还会把链接与话术拆散。用户在 P3 拷问中明确决定取消分段。否决。
- **让 LLM 自行换行排版、程序原样发送**：ADB 文本注入不支持换行，原样发送会丢字符/串行。否决，改为空白折叠。

## Consequences

- 优势：链路简单（一次 @ = 一次调用 = 一条消息）；回复话术与小程序链接始终同条出现，符合提示词的引导结构。
- 代价：超长回复没有程序兜底，长度完全依赖提示词约束与模型遵从度；若日后模型频繁超长，需重新评估恢复程序切分。
- 影响：P2 多段语义（第 1 段 @、后续纯文本）取消——唯一一条回复即带 @ 提及；CONTEXT.md「一次 @ 的多段回复」词条改写；队列/状态机/截图机制不受影响。
