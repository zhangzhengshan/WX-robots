# 出站消息走纯 ADB UI 自动化

> **适用范围（2026-09-15 P4 起，见 ADR-0008）**：本 ADR 仅约束 **P3 @回复路径**（需要 @提及、即时对话，官方 API 不支持）。P4 定时宣传改走企业群发 API（add_msg_template）建任务 + ADB 进群发助手点确认的混合链路，不再走本 ADR 的「在群内直接发言」方式。

需要在企业微信外部客户群中自动发送消息。官方 API 不支持外部群机器人任意发言（群 webhook 仅限内部群；群发助手需手动点击发送；微信客服是另一个入口），因此出站只能走非官方路径。

## Decision

通过 ADB 在 MuMu 模拟器中操作企业微信 UI 发送消息：`uiautomator dump` 定位控件、`input tap/text` 模拟触摸和输入、`screencap` 截图验证。不在设备上安装任何 agent（不引入 uiautomator2/atx-agent）、不 hook 企微进程（不用 Xposed/Frida）、不逆向私有协议。

## Alternatives Considered

- **无障碍服务 App（AutoX.js）**：能力更强但企微可读取已启用无障碍服务列表，AutoJs 系包名是公开的自动化指纹。否决。
- **Hook/改包（Xposed/Frida）**：企微有加固和注入检测，封号风险最高。否决。
- **私有协议逆向**：工作量大、企微协议变更频繁、检测手段成熟。否决。
- **官方 API**：外部客户群不支持机器人任意发言。否决（但入站仍用官方存档 SDK）。

## Consequences

- 优势：不引入设备端指纹；触摸事件经系统 InputManager 以 `TOOL_TYPE_FINGER` 送达，App 层无法从单个事件区分与真人手指的差异；不碰企微进程，不触发注入检测。
- 风险：行为模式（频率、节奏、内容）仍是检测面；ADB 调试开启本身是静态信号（但该号已在模拟器稳定登录，信号已被接受）。
- 约束：控件定位依赖企微 UI 布局，版本更新可能导致定位失效（用 text 属性而非混淆 resource-id，降低脆弱性）。
