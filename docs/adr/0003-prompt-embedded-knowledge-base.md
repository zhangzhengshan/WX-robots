# 知识库直接嵌入提示词，不做 RAG

机器人需要用企业上传的文档回答客户 @提问。

> 修订：2026-09-15 P3 落地时有两处调整，见后续 ADR：
> - 分段输出的决定被 **ADR-0006** 取代：AI 回复整段单条发送，不再 ≤150 字分段。
> - 文档格式被 **ADR-0007** 扩展：支持 .docx/.xlsx（Apache POI 抽取）+ Markdown/纯文本。

## Decision

知识库文档（Markdown/纯文本/docx/xlsx 转换后的纯文本，总字数上限 10 万字，超限单篇拒绝入库）在管理端维护，拼装为云端 LLM 系统提示词的固定区块，保存即热生效。AI 行为全部由提示词约束：命中知识库严格按原文回答、未命中可回答但受诚实边界约束、判断购买/了解饮品意图时在回复中附带购买引导。不做向量检索、不做上下文记忆、不做版本管理。

## Alternatives Considered

- **RAG（向量检索）**：文档量小（≤10 万字）、提问密度低，检索链路增加的复杂度（嵌入模型、向量库、召回调优）远大于收益。否决。
- **本地大模型**：模拟器宿主机资源有限，且回答质量不可控。否决。

## Consequences

- 优势：零检索基础设施，知识库更新即提示词更新，行为可解释（改提示词即改行为）。
- 风险：每次 AI 调用携带全量知识库，token 成本随文档增长；10 万字上限是该方案的硬边界，超出需重新评估是否引入 RAG。
- 约束：回复长度依赖模型遵守提示词约定（2-4 句）；分段切分机制曾作为长度兜底，已在 P3 按 ADR-0006 取消。
